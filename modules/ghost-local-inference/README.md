# ghost-local-inference — on-device LLM runtime for Ghost

Shared llama.cpp core (`cpp/`) with thin Kotlin (JNI) and Swift (C bridge)
wrappers, exposed to React Native as the `GhostLocalInference` Expo
TurboModule. React Native owns UI/state/chat; native code owns model
lifecycle, token generation, streaming, cancellation, hashing, and hardware
acceleration.

## Architecture

```
TS (lib/local/)          Native module
localRuntime.ts -------> GhostLocalInference (events: token)
modelManager.ts -------> hashFile / loadModel / unloadModel
pipeline.ts -----------> streamGenerate / cancel
```

Both platforms execute the same C++ file (`cpp/ghost_llama.cpp`) so
generation behavior is identical on Android and iOS.

## Android build (verified path)

llama.cpp is vendored at build time, not in git:

```bash
# in the EAS build environment / prebuild hook
git clone --depth 1 --branch <PINNED_TAG> https://github.com/ggerganov/llama.cpp /tmp/llama.cpp
# gradle passes -DLLAMA_CPP_DIR=/tmp/llama.cpp and -DHAVE_LLAMA_CPP is set
```

- `android/CMakeLists.txt` links the shared core + JNI bridge against it.
- `arm64-v8a` only; minSdk follows the app (root project) minSdk.
- GGUF validation (magic bytes) happens before `nativeLoad`; corrupt files
  are rejected with an actionable error, never a crash.

Pinned tag: verify the latest stable release at build time
(`https://github.com/ggerganov/llama.cpp/releases`) and record it in
`eas.json` build env (`LLAMA_CPP_TAG`). The C API surface used here
(`llama_model_load_from_file`, `llama_init_from_model`, `llama_tokenize`,
`llama_decode`, `llama_sampler_*`, `llama_token_to_piece`,
`llama_vocab_is_eog`) is the long-stable core; if a release renames any of
these, the NDK build fails loudly and `ghost_llama.cpp` must be updated to
match — that failure is the version gate.

## iOS build

`ios/` compiles `../../cpp/ghost_llama.cpp` into the module target and calls
it through the C interface declared in `cpp/ghost_llama.h` (add the bridging
header entry in the podspec generated by prebuild). Same GGUF validation,
CryptoKit streaming SHA-256, same cancellation semantics. Supported: iPhone
with 6GB+ RAM practical minimum (12 Pro and newer class); the
device-capability layer (`lib/local/devcap.ts`) reports per-model verdicts
and the UI only offers `compatible` models by default.

Apple's on-device model APIs were evaluated; a single GGUF core was chosen so
both platforms run byte-identical model artifacts and Ghost keeps one
registry, one manifest format, one verification path.

## Model artifacts

GGUF Q4_K_M language models (Qwen3-0.6B class for Mini, Qwen3-1.7B class for
Balanced), Apache-2.0 licensed, downloaded from Hugging Face over HTTPS,
SHA-256 verified, atomically installed. No weights ship in the app bundle.

## Failure behavior

| Case | Behavior |
| --- | --- |
| Module missing (Expo Go) | `health()` reports unavailable + "use a dev build" |
| `.so` not bundled | `backendStatus().linked=false`; load/generate throw `BACKEND_MISSING` |
| Corrupt GGUF | magic check rejects before native load |
| Generation cancelled | `cancel()` sets the flag; C++ loop stops between tokens |
| OOM on load | `llama_model_load_from_file` failure → `LOAD_FAILED` with reason |
